# Discovery — SEO, social and AI citation

How this site is made findable and quotable, what is deliberately in place, and
what still needs a human.

The goal is unusual for an SEO document: this project *wants* to be quoted at
length and cited, including by AI systems, because attribution is the growth
mechanism. Nothing here tries to withhold content to force a click.

## In place

**Crawlability**
- `robots.txt` allows everything, names the sitemap, and points crawlers at the
  JSON/CSV exports in preference to scraping HTML.
- `sitemap-index.xml` + `sitemap-0.xml`, generated by `@astrojs/sitemap`, listing
  all 115 pages.
- One canonical URL shape (no trailing slash), enforced in both Astro and
  Cloudflare so canonical tags never point at a URL that redirects.
- `<meta name="robots" content="index, follow, max-snippet:-1,
  max-image-preview:large">` — full snippets and large previews are wanted.
- `electiontracker.com.au` 301s to the canonical domain; the `workers.dev`
  hostname is disabled. No duplicate content on any hostname.

**Per page**
- Unique `<title>` and meta description on every page.
- Canonical URL.
- Open Graph + Twitter card, with a 1200×630 image.
- Semantic HTML: one `h1`, ordered headings, real `<table>` markup with
  `<caption>`, `<th scope>` and visually-hidden captions.
- All substantive content is indexable text. The coverage matrix is HTML links
  with accessible names, not a canvas — its data is also offered as a plain
  table.

**Structured data** (JSON-LD `@graph` on every page)
- `Organization` + `WebSite` sitewide, so citations attribute the right body.
- `Dataset` on the homepage and `/data`, with every JSON and CSV file as a
  `DataDownload`, licence and spatial/temporal coverage.
- `BreadcrumbList` on district and party pages, matching the visible breadcrumb.
- `WebPage` on district pages, `Organization` on party pages.

**For AI systems**
- `/llms.txt` — a guided index of the dataset in the emerging convention:
  what the project is, the coverage caveat stated up front, links to every
  export, and the status vocabulary defined.
- The coverage caveat travels with the data: it is a field inside
  `coverage.json`, not only prose on a page, so a machine reading the file
  cannot miss it.
- Licence and attribution stated in `robots.txt`, `llms.txt`, the footer, the
  terms and the JSON-LD.

**Verification**
- Google Search Console: verified by DNS (`sc-domain:electiontracker.au`),
  which covers every subdomain and protocol. A backup HTML verification file is
  also served, so verification survives a DNS change.

## Still needs a human

1. **Submit the sitemap** in Search Console → Sitemaps →
   `https://electiontracker.au/sitemap-index.xml`. DNS verification alone does
   not queue the site for crawling.
2. **Bing Webmaster Tools** — import from Search Console; it takes a minute and
   covers Bing, DuckDuckGo and Copilot.
3. **IndexNow** — Cloudflare has a one-click integration (site → Settings →
   IndexNow). Worth enabling: it pushes changes to Bing and Yandex immediately
   rather than waiting for a crawl, which suits a dataset that changes daily
   during a campaign.
4. **Facebook sharing debugger** — run the homepage through it once so Meta
   caches the new `og:image`, otherwise early shares may show nothing.

## Deliberately not done

- **No analytics.** The privacy policy claims no tracking, and that claim was
  verified against live response headers. Adding analytics later means changing
  that page first, honestly.
- **No `Person` schema for candidates.** Tempting for rich results, but it would
  assert structured claims about named living people well beyond what the
  sources support. The methodology's restraint outranks the SEO upside.
- **No keyword-stuffed landing pages** for seat names. District pages already
  exist, are genuinely useful and carry real data; manufacturing more would
  dilute them.

## Not to break

The trailing-slash agreement between `site/astro.config.mjs` and
`wrangler.jsonc`, and the canonical/sitemap consistency that depends on it. If
canonical tags start pointing at redirecting URLs again, check those two files
first.
